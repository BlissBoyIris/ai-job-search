# Job Desk

A local dashboard for this repo's `/scrape`, `/rank` and `/apply` workflows.

Open it by double-clicking `Start Job Desk.command` in the repo root (Mac). On Linux, run `npm install && npm run build && npm run start` in this folder and go to http://127.0.0.1:3300. It only listens on your own machine. Windows is not supported yet (the run launcher assumes a Unix shell and `python3`). Run `/start` in Claude Code first, so the dashboard knows what you are looking for.

- **Scrape** (`lib/fastscrape.ts` + `tools/scrape_run.py`): a script runs the searches (freehire, LinkedIn, open remote-board feeds, and the careers pages in `job_scraper/watchlist.json` if you keep one), applies your `my_search.json` filters and dedup with no model, then one Haiku call per 60 titles sorts them high/medium/low (low is stored as skipped). Posting text is cached in `job_scraper/postings/` so nothing fetches it twice. About 2 minutes and ~$0.01. The searches are built from the job titles in `my_search.json`; to tune them, copy `job_scraper/queries.example.json` to `job_scraper/queries.json` and edit it (git ignores it). **Broad** adds its `broad_runs` LinkedIn queries.
- **Rank** (`lib/fastrank.ts`): reads cached postings (or fetches them with scripts, Haiku only for JavaScript pages), scores 5 per Sonnet call against `04-job-evaluation.md`, and writes back through `tools/rank_state.py apply` + `sweep`. About 2 cents per job; up to 100 per click. `FAST_RANK_MODEL=haiku` makes it cheaper still.
- The original agent versions (`runScrapeAgent`, `runRankAgent` in `lib/runner.ts`) still exist but the buttons no longer use them. The table refreshes every few seconds from `job_scraper/seen_jobs.json`.
- **Write CV and cover letter** is the fast path (`lib/fastapply.ts`): scripts fetch and gate the posting, ONE model call writes both LaTeX files, then they are compiled and page-checked (a second call only if a page count or compile is off). About 1 minute and ~$0.15-0.20 per job. Model: `FAST_APPLY_MODEL` (default `sonnet`). **Write CVs for top N** queues several, three at a time.
- **Deep version with research** runs the full `/apply` agent (company research, reviewer pass). About 5-10 minutes and ~$2.50 per job.
- **Get answers** drafts screening-question answers grounded in your profile, with copy buttons.
- **Remove weak fits (N)** sits next to the job count in the Open list. It skips every ranked Weak Fit / Poor Fit job and every unranked job the scrape rated low, except jobs that already have a CV. Skipped jobs never come back on a scrape. Select rows and press **Delete** to remove specific ones instead.
- **Paste posting**: when a posting page can't be read (Cloudflare, login wall, JavaScript-only, or Rank gave up after 3 tries) the job shows a yellow **Paste posting** tag and a box in its panel. Paste the job description and press **Use this posting and write CV + cover letter**: the text goes through `tools/posting_guard.py`, is saved to `job_scraper/postings/`, the job returns to `new` (so Rank scores it from your text), and the fast CV run starts. Every other job has a small "Posting text wrong or missing? Paste it yourself" fold-out that does the same.
- **Save for later** (button on a job, or tick several in Open and press **Save N for later**) moves good jobs you will apply to later into the **Saved for later** list. Saved jobs are never removed by Remove weak fits or Delete, never picked by Write CVs for top N, and stay listed (marked Closed) if the posting closes. The button on the job moves it back to Open.
- **Deleted jobs never come back.** Delete and Remove weak fits mark the job skipped by the dashboard. A later scrape drops reposts of it (same company, title equal or one containing the other, tracking parameters ignored), `/rank` never re-scores it, and copies of it already in the list are removed at the same time. Jobs you saved or applied to are never swept up this way.
- **Mark as applied** updates `job_search_tracker.csv`, so the job never comes back and the counter goes up.

Claude Code comes from the VS Code extension (set `CLAUDE_BIN` to use another copy). Runs use your Claude account. Run logs are in `.data/runs/` and dashboard results in `.data/apps.json`.

After changing code here, run `npm run build` again before `npm run start`.
